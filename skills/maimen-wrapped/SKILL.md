# 麦门画像（maimen-wrapped）

读取用户自己的麦当劳历史订单，生成一份故事卡片流报告（类 Spotify Wrapped）。

## 前置条件

用户必须已配置麦当劳 MCP 连接器。若尚未配置，引导用户：

1. 访问 <https://open.mcd.cn/mcp> 用手机号验证登录
2. 点击右上角「控制台」→「激活」申请 MCP Token
3. 在 WorkBuddy 的【专家·技能·连接器】→【连接器】→【自定义连接器】→【配置 MCP】中填入：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_TOKEN"
      }
    }
  }
}
```

4. 启用 `mcd-mcp`

⚠️ 不要向用户索要 Token 明文，不要将 Token 写入任何文件。

## 执行流程

### 第 1 步：拉取数据（严格按此顺序）

依次调用以下 mock 工具，注意 `order-list` 与 `query-order` 是数据主源：

| 顺序 | 工具 | 参数 | 失败处理 |
| --- | --- | --- | --- |
| 1 | `now-time-info` | `{}` | 忽略，用当前时间 |
| 2 | `order-list` | `{}` | 必须成功，否则终止并告知用户 |
| 3 | `query-order` | `{"orderId": "<订单号>"}` | 对每单调用；单条失败则跳过该单 |
| 4 | `list-nutrition-foods` | `{}` | 失败则热量相关卡片降级 |
| 5 | `query-my-account` | `{}` | 忽略 |
| 6 | `available-coupons` | `{}` | 忽略 |
| 7 | `query-my-coupons` | `{}` | 忽略 |
| 8 | `campaign-calendar` | `{}` | 忽略 |

调用 `query-order` 时注意：若订单数量较多，分批处理，不要一次性发起过多请求（官方限流 600 次/分钟）。

### 第 2 步：聚合统计

按以下口径计算。**字段缺失时不得编造数据**，直接隐藏对应卡片。

**基础指标**
- 订单总数 = 订单条数
- 统计区间 = 最早订单日期 ~ 最晚订单日期
- 总花费 = 各单金额之和（若无金额字段 → 隐藏花费卡）
- 客单价 = 总花费 / 有效金额订单数

**餐品频次**：统计订单内所有餐品（含数量），取 Top 5

**时段分布**（需下单时刻，否则隐藏该卡）：
- 早餐 5:00-10:00、午餐 10:00-14:00、下午茶 14:00-17:00、晚餐 17:00-21:00、夜宵 21:00-次日 5:00

**月度分布**：按 `YYYY-MM` 分组计数，标注峰值月

**营养累计**：
- 将订单餐品名匹配到 `list-nutrition-foods` 的营养数据
- 匹配策略：① 归一化精确匹配（去括号内容、规格后缀、空白）② 相似度 ≥ 0.65 模糊匹配 ③ 手动映射表兜底
- 累计热量 = Σ(餐品热量 × 数量)；计算匹配率并如实展示
- 单位换算：若营养表单位为 kJ，需除以 4.184 转为 kcal

### 第 3 步：判定称号

按以下顺序，首个命中即采用：

| 条件 | 称号 |
| --- | --- |
| 夜宵占比 > 30% | 深夜麦乐送战士 |
| 早餐占比 > 40% | 早餐狂魔 |
| 单品的订单占比 > 30% | 「{餐品简称}」信徒 |
| 外送占比 > 70% | 麦乐送 VIP |
| 客单价 < 25 元 | 穷鬼套餐守护者 |
| 客单价 > 60 元 | 麦门大户 |
| 订单数 ≥ 100 | 麦门资深信徒 |
| 兜底 | 稳健干饭人 |

同时给出称号理由（引用具体数字）。

### 第 4 步：生成报告

使用项目模板 `src/maimen_wrapped/templates/report.html` 生成单文件 HTML，或直接运行：

```bash
python -m maimen_wrapped --out output/maimen-wrapped.html
```

若用户环境中无 Python 环境，按模板结构直接拼装 HTML（10 张卡片，暖色系轮换，见下方规范）。

## 卡片规范

10 张 9:16 全屏卡片，scroll-snap 逐张翻阅：

| # | 卡片 | 核心内容 |
| --- | --- | --- |
| 1 | 封面 | 标题 + 统计区间 + 「开启你的麦门之旅」按钮 |
| 2 | 总单数 | 超大数字（120px+）+ 频率文案 |
| 3 | 花费 | 总额 + 奶茶换算（金额缺失则跳过） |
| 4 | 本命餐品 | Top 5 横向条形图 + 冠军特写 |
| 5 | 干饭时钟 | 五时段柱状图（无时刻则跳过） |
| 6 | 月度节奏 | 逐月柱状图 + 峰值月 |
| 7 | 热量 | 累计千卡 + 巨无霸/慢跑小时换算（匹配率 < 50% 则降级） |
| 8 | 省钱 | 可领券/已有券/积分 + 过期提醒 |
| 9 | 彩蛋 | 错过的活动列表 |
| 10 | 称号 | 称号徽章 + 四格数据 + 仓库地址 |

**配色**：暖色系轮换（#C8102E / #B00E22 / #E8590C / #F77F00 / #7A0E1D / #D94F04 / #A31621 / #E85D04 / #6B0F1A / #8C0E20），文字 #FFF8EC，每卡一个半透明圆形装饰。

**文案基调**：梗化但克制。示例：
- 「板烧鸡腿堡见了你 47 次，真爱无疑」
- 「深夜 11 点的麦乐送，是你和这座城市的秘密」
- 「累计热量 ≈ 190 个巨无霸。好消息：快乐不计入热量」

**禁止**：不使用麦当劳 logo、金拱门图形、官方字体或任何商标素材；图标一律用 emoji 或 Unicode 符号。

## 硬性约束

- **只读**：绝不调用 `create-order`、`cancel-order`、`draw-lottery`、`mall-create-order` 等写操作工具
- **不编造**：字段缺失时隐藏卡片，不估算、不虚构
- **不落盘敏感数据**：订单原始数据仅存本地临时目录，不写入仓库
- **免责声明**：报告底部标注「本报告由开源项目 maimen-wrapped 生成，非麦当劳官方产品」，热量数据标注「估算，不构成营养建议」

## 输出

生成后告知用户：
1. 报告文件路径
2. 核心数据摘要（总单数、区间、称号）
3. 提示用浏览器打开并点击封面卡开始翻阅
